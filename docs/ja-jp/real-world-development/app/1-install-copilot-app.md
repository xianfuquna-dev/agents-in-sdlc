**[GitHub Copilot app][about-copilot-app]** は、エージェント主導の開発に使うデスクトップ アプリケーションです。GitHub Copilot CLI を基盤として GitHub とネイティブに統合されているため、リポジトリ、ブランチ、CI パイプラインをすぐに利用できます。自分だけで作業するのではなく、それぞれ分離されたワークスペースで複数のエージェントを並列に指示し、繰り返し作業を自動化するワークフロー向けに設計されています。Node.js をインストールし、プロジェクトのコピーを準備できたので、次はアプリをインストールしてリポジトリを接続します。

このレッスンでは、次のことを行います。

- GitHub Copilot app をインストールしてサインインします。
- GitHub リポジトリからプロジェクトをアプリに追加します。
- テンプレートから作成されたバックログなど、ワークスペースを確認します。
- アプリについて学ぶために、簡単なチャットを試します。

## シナリオ

チームでは、増え続けるバックログに取り組むために AI エージェントを導入しています。Copilot app を使うと、Issue の選択、エージェントの実行、変更のレビュー、プルリクエストのマージを 1 か所から指示できます。このレッスンでは、アプリをインストールして接続し、プロジェクトについての会話を始められるようにします。

> [!NOTE]
> 対象となる Copilot プランが必要です。Copilot Free、Copilot Student、またはいずれかの有料プラン (Pro、Pro+、Business、Enterprise) を利用してください。Copilot Business または Copilot Enterprise の場合、管理者が **GitHub Copilot app** ポリシーを有効にしておく必要があります。

## GitHub Copilot app をインストールして構成する

GitHub Copilot app を使うには、まずアプリをインストールします。Windows、macOS、Linux 向けのバージョンが用意されています。アプリをインストールして認証し、Tailspin Toys リポジトリを追加しましょう。

1. ブラウザーで [GitHub Copilot app のランディング ページ][download-app]を開きます。
2. 使用しているプラットフォーム向けのアプリをダウンロードし、ランディング ページにある手順に従ってインストールします。
3. インストール後、アプリを開きます。
4. **Sign in to GitHub** を選択し、画面の指示に従って認証します。データ レジデンシーを使用する GitHub Enterprise Cloud の場合は、**Use GitHub Enterprise** を選択し、求められたら `*.ghe.com` のホスト名を入力します。GitHub Enterprise Server はサポートされていません。
5. オンボーディングでリポジトリの選択を求められたら、テンプレートから作成した Tailspin Toys リポジトリを選択します。リポジトリの選択をスキップして、オンボーディング後にプロジェクトを追加することもできます。
6. テーマを選ぶよう求められたら選択し、オンボーディングを完了します。
7. サイドバーの **Sessions** の下にリポジトリが表示されているか確認します。すでに一覧にある場合は、もう一度追加する必要はありません。
8. リポジトリがまだ接続されていない場合は、**Sessions** の横にある **+** を選択して新しいセッションを作成し、**Add GitHub repository** を選びます。前提条件のレッスンで控えた owner と repository の名前を使います。
9. リポジトリがサイドバーに表示されることを確認します。ここで使うレイアウトでは、`tailspin-toys` などのリポジトリ フォルダーが **Sessions** の下にまとめられ、それぞれのリポジトリの下に個々のセッションが表示されます。

## ワークスペースを確認する

プロジェクトを接続したら、アプリの使い方を確認しましょう。サイドバーには、次の領域があります。

- **New** - ここから Copilot との新しいチャット セッションを開始できます。
- **Pull requests** - アプリの GitHub ネイティブ統合を通じて表示されるプルリクエストです。アプリを離れずに、プルリクエストを参照して絞り込み、CI の状態を確認し、レビューできます。
- **Issues** - 同じように表示される Issue です。Issue を参照して絞り込み、Issue からセッションを開始できます。
- **Automations** — スケジュールまたはオンデマンドで実行する、保存済みのエージェント タスクです。To-do リスト、定期的なプロジェクトの保守、その他の面倒な作業を任せるのに役立ちます。まとめのレッスンでは次のステップとして紹介しますが、別の演習ではありません。
- **Customize** - MCP サーバー、プラグイン、スキルなどのコンポーネントを使って Copilot app に機能を追加します。Playwright MCP の設定に使用します。
- **Chats** — ブランチや専用のワークスペースを必要としない、質問やブレインストーミング向けの簡単な会話です。最初のチャットを始めると、このセクションが表示されます。表示されていない場合は、**Sessions** の横にある **+** を選択して最初のチャットを開始します。
- **Sessions** — リポジトリ フォルダーと、その中のエージェント セッションをまとめたものです。`tailspin-toys` などのリポジトリ名を選択するとリポジトリ ビューが開き、その下にあるセッションを選択するとその会話に戻ります。セッションはそれぞれ分離された独自のワークスペースで実行されるため、変更が競合せず、複数のセッションを同時に実行できます。星評価を追加するレッスンで最初のセッションを開始します。

ワークショップを進めながら、ワークスペースを詳しく確認します。

> [!TIP]
> 迷ったときは Copilot に質問しましょう。操作方法が分からない場合や、何かが可能か知りたい場合は、Copilot が案内してくれます。

### 用意されたバックログを確認する

バックログのないプロジェクトはほとんどなく、Tailspin Toys も例外ではありません。テンプレートから作成したリポジトリに用意されたバックログを確認しましょう。

1. サイドバーの **Sessions** の下にある Tailspin Toys のリポジトリ フォルダーを選択します。フォルダーの下にある個別のセッションは選択しないでください。次に、リポジトリの上部ナビゲーションで **Issues** を選択します。
2. Issue 番号を決めつけず、次のタイトルを探します。

   - Allow users to filter games by category and publisher
   - Update our repository coding standards

3. Issue を選択して詳細を読みます。各 Issue はエージェント セッションを開始する場所にもなります。簡単な最初の変更を済ませた後、フィルター機能の Issue から作業します。

> [!NOTE]
> **Issues** と **Pull requests** の一覧には、Copilot app に追加したリポジトリの項目だけが自動的に表示されます。ほかのリポジトリの作業項目を確認するには、そのリポジトリをアプリに追加してください。

## クイックチャットを試す

アプリに慣れるには、アプリ自体について質問するのが効果的です。その用途には**クイックチャット**が適しています。クイックチャットでは、ブランチや worktree を作成せずに質問やブレインストーミングができます。セッションを必要としない簡単な質問に便利です。

1. サイドバーの **Chats** の横にある **+** を選択して、新しいチャットを開きます。**Chats** がまだ表示されていない場合は、**Sessions** の横にある **+** を選択して最初のチャットを始めます。その後 **Chats** が表示されます。
2. アプリのセッションがどのように動作するかを尋ねます。

   ```plaintext
   How does the GitHub Copilot app use worktrees?
   ```

3. 会話ビューで回答を読みます。各セッションが分離された独自の Git worktree で実行されるため、変更が競合せず、複数のエージェントを並列に実行できることが分かります。会話は続けることも、新しいチャットを開始することもできます。

## まとめと次のステップ

GitHub Copilot app をインストールしてプロジェクトを接続し、ワークスペースを確認しました。次のことを学びました。

- アプリをインストールして GitHub にサインインする
- GitHub リポジトリからプロジェクトを追加する
- ワークスペースを確認し、**Issues** で用意されたバックログを見つける
- クイックチャットで、その場限りの質問をする
