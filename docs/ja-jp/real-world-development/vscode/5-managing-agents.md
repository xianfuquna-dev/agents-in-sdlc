GitHub Copilot をエージェント モードで使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、ツール呼び出しやファイルの編集をリアルタイムで確認できます。エディターを離れずに差分を確認し、個々の変更を採用または取り消し、追加のプロンプトで会話を方向付けて作業を改善できます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して採用します。
- 作業中のセッションに指示して、ハイ コントラスト モードとともにライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタムエージェントは、ハイ コントラスト モードを実装しています。作業中、デザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じる利用者のため、ライト モードの切り替えも追加してほしいとのことです。新しい会話を最初から始めず、既存のセッションを方向付けて機能を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案する編集を確認できます。各ファイル編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りや編集、実行許可を求めるターミナル コマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャットに表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントに別の方法を試させます。
4. チャットの上部にある **Files changed** の表示を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などでツール呼び出しの許可を求められると、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最後に変更内容の概要が表示されます。

## ライト モードを追加するようエージェントに指示する

ハイ コントラスト モードができたので、同じ会話でライト モードの切り替えも追加します。同じチャット セッションを続けると、エージェントは以前の作業、変更したコンポーネント、スタイル設定、local storage を使った設定の保持方法を引き続き参照できます。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認し、ライト モードの追加を提案します。
3. ハイ コントラスト モードの場合と同じように、新しい編集を確認します。各差分で **Keep** または **Undo** を選択します。
4. エージェントが希望と異なる方向に進んだ場合（たとえば、望まない方法でトグル UI をリファクタリングしようとした場合）は、チャット入力欄の隣にある **Stop** ボタンで停止し、内容を明確にした追加プロンプトを送信します。

> [!TIP]
> 実行中のセッションを方向付けると、最初からやり直すより短時間で作業できます。追加プロンプトを使って調整（「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う」）、方向修正（「3 つ目のトグルは追加せず、既存の設定パネルにライト モードを組み込む」）、範囲の拡張（「両方の切り替えにキーボード ショートカットも追加する」）を依頼できます。

## 作業内容をレビューする

作業をコミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更したファイルをいくつか開き、差分を確認します。カスタムエージェントが指定したアクセシビリティの手法（ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保持など）が使われていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使って、実行中のセッションを監視して方向付けました。各ファイルの編集を確認して採用または取り消し、コンテキストを保ったまま追加プロンプトを送信して作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視する
- 個々のファイル編集を採用または取り消す
- 作業中のセッションに追加プロンプトを送り、方向を調整する

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボを通してローカルのカスタムエージェントが作成した変更をレビューします。
